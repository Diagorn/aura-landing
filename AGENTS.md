# AGENTS.md — aura-landing

Правила работы с репозиторием. Файл загружается агентам при старте сессии — держим его
компактным и актуальным для стека проекта.

## Проект

- **Тип:** одностраничный лендинг трекера эмоций Aura (SPA). Нет SSR, роутинга и запросов к API.
- **Стек:** React 19 + Vite + TypeScript (strict), TailwindCSS v4, framer-motion, lucide-react.
- **Команды:** `npm run dev` · `npm run build` · `npm run preview`.
- **Перед коммитом** прогонять `npm run build`.

## Структура

```
src/
  App.tsx            # композиция страницы: фон, шапка, секции, футер
  main.tsx           # вход; подключение шрифтов (@fontsource) и стилей
  index.css          # Tailwind v4: токены тем, утилиты (glass, header-glass, text-gradient,
                     #   noise, pulse-soft, chart-dot), keyframes
  config.ts          # AUTH_URL — адрес внешнего приложения авторизации
  i18n/              # ВСЕ тексты: types.ts (Dictionary), ru.ts, index.ts (useTranslation)
  lib/animation.ts   # общая easing-кривая для framer-motion
  components/        # секции лендинга и переиспользуемые элементы (Reveal, Logo, ThemeToggle...)
```

## Конвенции проекта

### Тексты и локализация (i18n)
- Никаких текстовых строк прямо в JSX — только через `useTranslation()` из `src/i18n`.
- Добавляя UI-элемент, сначала опиши ключи в `i18n/types.ts`, затем заполни `i18n/ru.ts`.
- Новый язык = новый файл `i18n/<locale>.ts` по интерфейсу `Dictionary` + регистрация в
  `i18n/index.ts`. Компоненты при этом не меняются.

### Темы
- Переключение классом `.dark` на `<html>`; выбор хранится в `localStorage`, ключ `aura-theme`.
- Тема применяется инлайн-скриптом в `index.html` **до** монтирования React — не удалять
  (защита от вспышки неправильной темы).
- Цвета фона/текста — только семантические токены (`bg-bg`, `text-fg`, `text-muted`,
  `border-line`, `bg-card`, `bg-card-strong`), объявленные в `@theme inline` через CSS-переменные
  из `:root` / `.dark`. Не хардкодить их в компонентах.
- Каждый компонент обязан одинаково хорошо выглядеть в обеих темах.

### Внешняя авторизация
- Все кнопки «Войти» и CTA ссылаются на `AUTH_URL` из `src/config.ts`
  (`import.meta.env.VITE_AUTH_URL ?? '/'` — пока заглушка на сам лендинг).
- Внутренних маршрутов авторизации не создавать — за неё отвечает другое приложение.

### Анимации
- Появление секций при скролле — обёртка `Reveal` (framer-motion, `viewport.once = true`).
- Анимация атрибутов SVG (пульс точки графика) — **SMIL `<animate>`**, а не CSS-transform:
  предсказуемо во всех браузерах и без «вспышек»; базовое состояние элемента — `opacity="0"`.
- Ключевые кадры оформляются через `--animate-*` в `@theme`; циклы — плавные
  (ease-in-out, мягкое проявление из нуля), без резких перезапусков.
- Слушатели скролла/resize — `{ passive: true }`, снятие в cleanup у эффекта.

### Tailwind v4
- Тёмная тема: `@custom-variant dark (&:where(.dark, .dark *))`.
- Кастомные утилиты — через `@utility`.
- Шапка использует `header-glass` (линия только снизу). Рамка по периметру фиксированной
  шапки читается как «белая рамка» при скролле — не возвращать.

## Правила React

- **Считай производное в рендере.** Не дублируй производные значения в state и не
  синхронизируй их эффектами.
- **Не мемоизируй простое.** `useMemo` не для выражений с примитивным результатом —
  накладные расходы на хук дороже вычисления.
- **Не объявляй компоненты внутри компонентов.** Новый тип на каждом рендере = полный
  remount (потеря state/фокуса, перезапуск анимаций). Выноси на уровень модуля, данные — props.
- **Функциональные обновления state:** `setX(prev => ...)` — стабильные колбэки без
  stale-замыканий и лишних зависимостей.
- **Ленивая инициализация state:** дорогое начальное значение (localStorage, парсинг,
  построение индексов) — через `useState(() => ...)`.
- **Явный условный рендеринг:** тернарник вместо `&&`, если условие может быть `0`/`NaN`.
- **Статичное — на уровень модуля:** константы и предрасчёты (точки графика, SVG-пути,
  массивы иконок/акцентов) считаются один раз вне компонента, а не на каждом рендере.

## Правила JavaScript

- Иммутабельность state/props: `toSorted()` вместо `sort()`, spread вместо мутаций.
- Ранние `return` вместо вложенных условий.
- По возможности один проход по массиву вместо цепочки `.filter().map()`;
  `flatMap` для «отобразить и отфильтровать».
- `Set`/`Map` для проверок принадлежности, если проверок много.
- Регулярные выражения — на уровень модуля, не создавать в рендере.

## Бандл

- Иконки — именованные импорты из `lucide-react` (tree-shaking работает); не импортировать
  библиотеку целиком.
- Тяжёлые зависимости (библиотеки чартов, редакторы), когда появятся, — только через
  динамический импорт (`React.lazy`).
- Аналитика/метрики (когда появятся) — подключать после монтирования, не в критическом пути.
- Шрифты — self-hosted `@fontsource-variable/*` (Manrope, Unbounded; кириллица включена).
  Google Fonts по ссылкам не подключать.

## Чего в проекте нет — не применять

SSR/RSC, Server Actions, `React.cache()`, `after()`, Next.js-конфигурация, роутинг,
SWR/react-query, запросы к API. Разделы старых гайдов про серверный рендер неактуальны.
